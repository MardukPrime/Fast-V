# 订阅与节点管理测试

本文档用于验证订阅导入、节点解析、当前节点选择、启停和 TCP 连通性测试。

## 1. 准备测试订阅

仓库提供测试文件：

```text
test/fixtures/subscription-sample.txt
test/fixtures/subscription-sample.b64
```

使用本地 HTTP 服务：

```bash
python -m http.server 8089 --directory test/fixtures
```

订阅地址：

```text
http://127.0.0.1:8089/subscription-sample.b64
```

该订阅包含 4 个假节点：

- VMess
- VLESS
- Trojan
- Shadowsocks

这些地址不可连接，仅用于解析和界面测试。

## 2. 添加订阅

1. 打开订阅页面。
2. 名称填写为本地测试订阅。
3. 填入上面的本地地址。
4. 点击添加订阅。

预期结果：

- 订阅添加成功。
- 节点数量为 4。
- 订阅状态为正常。

## 3. 查看节点

1. 点击订阅卡片上的节点按钮。
2. 检查节点弹窗。

预期结果：

- 显示 4 个节点。
- 协议、地址、端口正确。
- 可以将节点设为当前节点。

## 4. 节点管理

1. 打开服务器页面。
2. 搜索节点名称、地址或订阅名称。
3. 切换协议筛选。
4. 切换订阅筛选。
5. 点击测试当前列表。

预期结果：

- 筛选结果正确。
- 当前节点有选中标记。
- TCP 测试会返回成功或失败原因。
- 测试结果不会修改节点启用状态。

## 5. 启停和当前节点

1. 禁用一个非当前节点。
2. 确认状态变为禁用。
3. 尝试将它设为当前节点。

预期结果：

- 禁用节点不能设为当前节点。
- 禁用当前节点时，当前节点会被清空。
- 重新启用后可以再次设为当前节点。

## 6. 更新订阅

1. 在订阅页面点击更新。
2. 再打开节点列表。

预期结果：

- 节点数量保持稳定。
- 相同 source key 的节点保留原 ID。
- 用户设置过的启用状态在更新后保留。
- 更新失败时旧节点不会被清空。

## 7. 删除

1. 删除单个节点。
2. 删除整个订阅。

预期结果：

- 删除节点后订阅节点数量减少。
- 删除订阅后其全部节点消失。
- 删除当前节点后当前节点为空。

## 8. 代理启动和本地入站测试

测试 fixture 使用假节点，不能访问真实远端。可以先验证本地代理启动、本地入站和测试链路：

1. 在服务器页面选择一个节点作为当前节点。
2. 在设置页面将代理模式设为直连。
3. 将代理测试地址设为本地 HTTP 服务，例如：

```bash
python -m http.server 8099 --bind 127.0.0.1
```

```text
http://127.0.0.1:8099/
```

4. 回到概览页面点击启动代理。
5. 确认状态显示本地 SOCKS/HTTP 入站地址，例如 `127.0.0.1:10808`。
6. 点击测试代理。

预期结果：

- Xray 配置生成成功。
- 本地入站端口可连接。
- 直连模式下测试地址返回 HTTP 200。
- 概览页运行节点区域显示节点名称、服务器地址、解析 IP、协议、订阅、本地入站、代理模式和 PID。
- 停止代理后端口关闭，Xray 进程退出。
- 关闭应用时 Xray 进程由 Job Object 一并清理。

真实代理链路测试需要将订阅替换为可连接的节点，并将代理模式改回规则分流或全局代理。
