# Xray-core

Xray-core is the first and primary proxy core used by FastV. It handles VMess, VLESS, Trojan, Shadowsocks, local SOCKS/HTTP inbounds, transport security, routing, DNS and traffic statistics.

## Why Xray-core First

- It covers the protocols and transports used by most v2rayN-compatible share links.
- It supports VMess, VLESS, Trojan and Shadowsocks outbounds.
- It supports RAW, WebSocket, gRPC, HTTPUpgrade and XHTTP transports.
- It supports TLS and REALITY.
- It provides routing, DNS, Mux, statistics and a gRPC API.
- It can be run as a separate process, keeping the Go desktop application independent from protocol implementation details.

## Supported Scope

### MVP

- Outbound protocols: VMess, VLESS, Trojan, Shadowsocks
- Transports: RAW, WebSocket, gRPC
- Security: TLS, REALITY
- Local inbound: SOCKS inbound with HTTP compatibility
- TUN: Xray TUN inbound on Windows with Wintun
- Mux: optional
- Routing: direct, proxy, block and domain/IP rules
- DNS: basic built-in DNS configuration
- Statistics: optional traffic counters through the Xray API

### Later

- HTTPUpgrade and XHTTP
- Hysteria, WireGuard and MASQUE outbounds
- Full rule sets and GeoSite/GeoIP management
- Advanced observability, balancing and per-process routing

## Local Inbound Note

Xray documents a SOCKS inbound that is compatible with SOCKS4, SOCKS4a, SOCKS5 and HTTP. FastV uses one local SOCKS inbound with `udp: true` as the default local entry, allowing the same port to serve SOCKS and HTTP clients. The system proxy points to the HTTP-compatible local endpoint.
