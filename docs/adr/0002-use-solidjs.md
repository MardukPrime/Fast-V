# ADR-0002: 使用 SolidJS 作为前端框架

- 状态：Accepted
- 日期：2026-10-31

## 背景

FastV 需要处理大量节点、实时日志、延迟状态和流量数据。前端框架不应成为高频 UI 更新的瓶颈，同时需要较成熟的 TypeScript 开发体验。

## 决策

使用 SolidJS + TypeScript + Vite：

- 使用 signals/store 做细粒度状态更新。
- 使用 TanStack Solid Virtual 处理大列表。
- 使用 Kobalte 作为无样式基础组件。
- 使用 uPlot 或 Canvas 绘制流量图表。
- 不使用 SSR。

## 后果

### 正面影响

- 无虚拟 DOM，更新成本低。
- 运行时体积小，启动快。
- 适合大列表和高频状态更新。

### 负面影响

- 组件生态小于 Vue/React。
- 复杂组件需要基于 Kobalte 自建或二次封装。

## 备选方案

| 方案 | 优点 | 缺点 | 未采用原因 |
|---|---|---|---|
| Vue 3 | 生态成熟、开发快 | 高频更新需更多手工优化 | 性能优先场景略逊 |
| React | 生态最大 | 虚拟 DOM 和重渲染成本 | 需要更多优化 |
| Svelte 5 | 编译型、性能好 | 生态和团队熟悉度不确定 | 作为次选保留 |
