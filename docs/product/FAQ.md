### Q1. 启动代理后浏览器或应用仍无法上网

**现象**

- 概览页显示代理「运行中」，但浏览器打不开网页，或只有部分应用能联网。
- 网络诊断的「代理出口」无法得到 IP，或直连出口正常而代理出口异常。

**原因**

- Windows 系统代理没有生效、指向了旧端口，或残留了上一次的代理设置。
- DNS 缓存异常，或系统 DNS 被污染。
- 当前节点不可用（服务器故障、订阅已过期、节点被禁用）。
- 本地端口被其他程序占用。
- 安全软件、防火墙拦截了本地回环或 TUN 流量。

**解决**

1. 打开 **网络诊断 → 网络救援**，点击「检测网络状态」，再点击「一键修复」。代理未运行时，修复会重置系统代理（并尽力清理 WinHTTP 代理）并刷新 DNS；代理运行中则会刷新 DNS 并重启本地代理。
2. 检查 **设置 → 客户端设置 → Windows 系统代理** 是否选择了正确模式；如果选择「关闭」，需要手动把应用代理指向 `127.0.0.1:10808`（端口以设置页为准）。
3. 打开 **网络诊断**，分别检测「直连出口」与「代理出口」。代理出口没有 IP 通常说明节点或本地代理链路有问题，可换一个节点后再试。
4. 运行 **网络诊断 → 一键自检**，确认本地端口、API 端口、配置校验与 GeoData 均正常。
5. 检查安全软件/防火墙是否拦截了 FastV 或 `xray.exe`，必要时把程序加入白名单。
6. 如果问题出现在系统代理模式与 PAC 模式切换之后，先停止代理再重新启动一次，让新配置完整生效。

### Q2. 关闭或退出 FastV 后无法上网，或仍有核心进程残留

**现象**

- 退出 FastV 后浏览器完全无法上网，提示代理连接失败。
- 或者代理已停止，但任务管理器中仍有 `xray.exe` 进程。

**原因**

- FastV 异常退出（崩溃、被强制结束、系统关机）时，未来得及恢复系统代理与 PAC 配置。
- 上一次的 WinHTTP 代理残留（影响系统更新与部分应用）。
- 其他代理客户端与 FastV 争抢系统代理设置。
- 内核进程因强制结束而没有被正常清理。

**解决**

1. 重新启动 FastV，打开 **网络诊断 → 网络救援**，执行「检测网络状态」与「一键修复」：代理未运行时会重置系统代理、尽力清理 WinHTTP 代理并刷新 DNS。
2. 如果已经无法启动 FastV，可在 Windows「设置 → 网络和 Internet → 代理」中手动关闭「使用代理服务器」，并确认「自动检测设置」没有被指向失效的 PAC 文件。
3. 打开任务管理器，若有残留的 `xray.exe`，结束该进程后再重启 FastV。
4. 检查是否同时运行了其他代理客户端；多个客户端同时修改系统代理会互相覆盖。
5. 若问题反复出现，进入 **设置 → 系统集成 → 环境清理**，清理残留的协议注册、开机自启项与 PAC 文件，然后导出诊断报告反馈。

### Q3. TUN 模式启动失败，或开启后无法联网

**现象**

- 开启 TUN 后启动代理报错，提示需要管理员权限、找不到 `wintun.dll` 或内核异常。
- TUN 已启动但所有网站都打不开，或系统路由异常。

**原因**

- 未以管理员身份运行，或拒绝了 UAC 提权。
- 未安装 Xray-core，或 `wintun.dll` 不在 `xray.exe` 同目录。
- 与其他 VPN、虚拟网卡或安全软件冲突。
- 代理本身未运行或节点不可用，TUN 没有可转发的出口。
- 开启了负载均衡或自动选路，TUN 下会回退/暂停部分能力。

**解决**

1. 打开 **网络诊断 → TUN 自检**，点击「检查 TUN」，按逐项结果处理：管理员权限、内核、`wintun.dll`、代理状态都会单独列出。
2. 确认以管理员身份运行 FastV；保存 TUN 设置或启动代理时 FastV 会请求 UAC 提权。
3. 进入 **设置 → 内核设置** 下载或更新 Xray-core，确认 `<数据目录>\cores\xray\` 下同时存在 `xray.exe` 与 `wintun.dll`。
4. 临时关闭其他 VPN / 虚拟网卡软件后重试；部分网络环境（如校园网、拨号网络）对 TUN 支持较差。
5. TUN 仍不可用时，点击 TUN 自检面板中的「切换回系统代理」一键回退（代理运行中会自动重启生效）。
6. 需要继续排查时导出诊断报告，其中包含 TUN 自检结果与平台信息。

### Q4. 代理运行中突然断流，日志显示核心异常退出

**现象**

- 使用过程中网络短暂中断，随后恢复；日志页出现核心退出、自动重启相关记录。
- 或者连续失败后代理进入「异常」状态，需要手动重启。

**原因**

- 节点服务器异常、网络波动或被服务商限速/阻断。
- Xray 配置不兼容或 GeoData 资源缺失。
- 系统资源不足、安全软件强制结束进程。

**解决**

1. 打开 **日志** 页查看 `error` / `warning` 级别的记录，确认核心退出原因。
2. FastV 默认开启「核心异常时自动重启」（**设置 → 系统集成 → 可靠性**）：核心非用户主动停止的异常退出会按 1 秒、2 秒、4 秒退避自动重启，最多连续 3 次；稳定运行 60 秒后计数重置；用户主动停止的代理不会被自动拉起。
3. 如果连续 3 次自动重启后仍然失败，代理会进入异常状态：此时切换节点、运行 **一键自检** 中的「Xray 配置校验」，或重启 FastV。
4. 若与特定节点相关，用「真实链路测速」确认节点质量，并把异常节点禁用。
5. 需要进一步定位时，导出诊断报告（含脱敏日志与自检结果）。

### Q5. 订阅添加失败或更新失败

**现象**

- 添加订阅时提示失败、超时或「未找到可用节点」。
- 更新订阅报错，节点列表为空或未变化。

**原因**

- 订阅地址无效、不是 `http://` / `https://`，或已过期/被重置。
- 当前网络无法直连订阅服务器（需要代理）。
- 订阅服务器限制了 User-Agent、地区或请求频率。
- 订阅内容格式不受支持（如不支持的协议类型、空内容、超过大小限制）。
- 下载超时（20 秒）或内容超过 5 MB。

**解决**

1. 确认订阅地址完整且以 `http://` 或 `https://` 开头；可先在浏览器中打开该地址确认能下载。
2. 在 **设置 → 客户端设置 → 订阅更新** 中确认「订阅更新失败时通过本地代理重试」已开启，并保持本地代理运行：直连失败时会自动经代理重试一次。
3. 如果服务商有 UA 限制，在该订阅的「设置 → 自定义 User-Agent」中填写服务商要求的 UA（最长 200 个字符）。
4. 确认订阅内容格式：支持分享链接、Base64 订阅内容与 Clash / Clash.Meta YAML；不支持的协议类型会被逐条跳过，如果全部被跳过会报「没有可用节点」。
5. 更新单个订阅失败不影响其他订阅；可点击「全部更新」重试，并在日志页查看具体错误。
6. 若错误信息为「直连与代理重试均失败」，通常说明订阅地址或服务商侧异常，请联系订阅提供方。

### Q6. 路由规则不生效

**现象**

- 某个网站没有被规则拦截/直连/代理，行为与预期不符。
- 修改规则后没有任何变化。

**原因**

- 规则从上到下匹配，前面的规则先命中；新规则排在了后面。
- 规则类型或内容写错（例如把域名后缀写成完整 URL）。
- 当前代理模式不是「规则分流」。
- 规则集订阅尚未成功更新，或规则集被禁用。
- GeoIP / GeoSite 规则需要运行时判定，无法用调试器离线确认。
- 进程分流规则仅在 Windows 上有效。

**解决**

1. 打开 **路由 → 规则调试器**，输入目标域名、IP、进程名、端口或协议执行调试，查看命中的规则、动作与来源（用户规则 / 规则集 / 默认出站）。
2. 如果规则顺序不对，使用行内「上移 / 下移」调整；命中的规则需排在更宽泛的规则之前。
3. 确认顶部栏代理模式：已启用的路由规则在三种模式下都会先参与匹配，全局/直连模式只改变「未命中规则的流量」的默认出站；如果期望完全忽略规则，请先禁用相关规则。
4. 检查规则是否处于启用状态，以及规则集是否「启用」且最近一次更新成功（更新失败会保留上一次成功内容）。
5. 修改规则后，代理运行中 FastV 会自动重启内核；如果行为仍未变化，确认代理确实在运行，并查看日志中的配置错误。
6. 进程分流请使用 Windows 进程名（如 `chrome.exe`），且该能力仅 Windows 支持。

### Q7. 延迟测速结果不准或与其他工具差异大

**现象**

- 节点延迟显示 300 ms，但用其他工具 ping 只有 50 ms。
- 多次测速结果波动明显，或测速超过预期时间。

**原因**

- FastV 的「测速」是真实链路 HTTP 延迟：会临时启动内核、建立真实代理连接并请求测试地址，包含 DNS、握手与 TLS 开销，通常高于 ICMP ping。
- 没有真实链路结果时会回退显示 TCP 连通性结果，两者含义不同。
- 测试地址不同、网络波动、节点拥塞都会影响结果。
- 批量测速会并发启动临时内核，可能受本机性能影响。

**解决**

1. 鼠标悬停延迟列，确认显示的是「真实链路延迟」还是「TCP 连通性」；两者的数值不应直接比较。
2. 在 **设置 → 客户端设置 → 代理测试地址** 中更换更稳定的测试地址（默认 `https://www.gstatic.com/generate_204`）。
3. 对同一节点连续测速 2–3 次，取较稳定的结果；单次结果受网络波动影响较大。
4. 节点分组可以单独设置测试 URL，留空时使用全局测试地址。
5. 以真实链路结果为选节点依据；如果代理实际可用但延迟数值偏高，可先在浏览器中实测访问速度。
6. 测速期间避免同时进行大流量下载或运行多个代理客户端。

### Q8. WebDAV 测试连接、上传或恢复失败

**现象**

- 点击「测试连接」失败，或上传/恢复时提示 HTTP 错误。
- 修改服务器地址后测试仍使用旧地址。

**原因**

- 地址不是完整的 `http://` / `https://` 地址，或服务器不支持 WebDAV。
- 账号密码错误、服务器要求应用专用密码、或未开启 Basic 认证。
- 远端路径没有创建/写入权限。
- 修改设置后没有先保存就执行操作。
- 证书不受信任、网络超时或备份超过大小限制。

**解决**

1. 填写服务器地址、用户名、密码与远端路径后，先点击「保存设置」，再执行「测试连接」。
2. 确认地址以 `http://` 或 `https://` 开头，且指向 WebDAV 根目录；部分服务（如 Nextcloud）需要填写 `/remote.php/dav/files/<用户>` 形式的地址。
3. 使用应用专用密码而非主账号密码；确认服务器允许 HTTP Basic 认证。
4. 确认账号对目标目录有写入权限；远端路径的父目录不存在时 FastV 会自动创建，但需要服务器允许创建。
5. 优先使用 HTTPS；自签名证书或企业证书可能导致连接失败，可先在浏览器确认证书链。
6. 上传/下载上限为 16 MB，测试连接约 30 秒、上传/恢复约 120 秒超时；网络较慢时请重试或更换网络。
7. 错误信息会包含 HTTP 状态码且不回显密码，可据此判断是认证失败（401/403）、路径错误（404）还是服务器错误（5xx）。
8. 「从云端恢复」会覆盖当前全部配置且无法撤销，操作前请确认，或先在本地创建配置快照。

### Q9. PAC 智能分流是什么，为什么有些程序仍不走代理

**现象**

- 开启 PAC 后，浏览器走代理，但某些程序仍直连或无法联网。
- 切换到 PAC 模式后行为似乎没有变化。

**原因**

- PAC 只能影响支持「自动代理配置（AutoConfigURL）」的程序（主要是 WinINet 应用，如浏览器）。
- PAC 模式仅 Windows 支持；私有与本地地址按脚本直连。
- 修改系统代理模式后需要重启代理才会生效。

**解决**

1. PAC 模式由本地生成的 `fastv.pac` 决定：私有地址与本地地址直连，其余请求走本地代理；FastV 会把 Windows 自动代理配置指向该文件。
2. 保存设置后停止并重新启动代理，使 PAC 配置生效；面板会提示「保存后需重启代理生效」。
3. 不支持系统自动代理配置的程序（部分游戏、命令行工具、独立客户端）不会读取 PAC：这类程序需要 TUN 模式，或手动把代理指向 `127.0.0.1:10808`。
4. 如果不再需要 PAC，切回「系统代理」或「关闭」模式并重启代理；FastV 会恢复原有自动代理配置并删除生成的 PAC 文件。
5. 需要确认 PAC 是否生效时，可在 Windows「设置 → 网络和 Internet → 代理」中查看「使用设置脚本」是否已指向 `file:///.../pac/fastv.pac`。

### Q10. 开机自启不生效，或 TUN 提示需要管理员权限

**现象**

- 勾选「开机自启」后，下次登录 Windows 没有自动启动 FastV。
- TUN 模式提示需要管理员权限，或每次启动都弹出 UAC。

**原因**

- 开机自启按当前 `Fast-V.exe` 的路径注册到当前用户的开机启动项；移动、重命名或重新安装程序后路径失效。
- 安全软件阻止了开机启动项写入。
- 开机自启只会以普通权限启动，不会自动获得管理员权限。
- TUN 模式必须要有管理员权限，并且需要内核同目录存在 `wintun.dll`。

**解决**

1. 在 **设置 → 系统集成 → 开机自启** 中关闭再重新开启一次，让 FastV 按当前程序路径重新注册；移动或重命名程序后也需要这样操作。
2. 检查安全软件/系统优化工具是否拦截了开机启动项，或将 FastV 加入允许列表。
3. TUN 模式需要管理员权限：保存 TUN 设置或启动代理时确认 UAC 提权；也可以右键 `Fast-V.exe` 选择「以管理员身份运行」。
4. 开机自启与 TUN 同时开启时，登录后可能仍需要确认一次 UAC；如果拒绝提权，TUN 无法工作，可改用系统代理或 PAC 模式。
5. 若 TUN 权限与依赖均正常但仍无法启动，打开 **网络诊断 → TUN 自检** 获取具体失败原因。

### Q11. 端口被占用，代理无法启动

**现象**

- 启动代理失败，日志提示端口被占用或本地代理异常。
- 网络诊断显示本地入站端口被其他程序占用。

**原因**

- 默认本地端口 `10808` 被其他代理软件或程序占用。
- 上次异常退出的 `xray.exe` 仍占用端口。
- 修改了 API / 统计端口，但与本地代理端口或其他程序冲突。
- 系统端口被其他服务临时占用。

**解决**

1. 打开 **网络诊断 → 网络救援** 执行检测；代理未运行时会检查本地入站端口是否被占用。
2. 关闭占用端口的程序，或在 **设置 → 内核设置 → 本地 SOCKS/HTTP 端口** 中更换一个空闲端口并重启代理。
3. 如果启用了 Xray API / 统计，确认 API 端口（默认 `10085`）与本地代理端口不同，且未被其他程序占用。
4. 打开任务管理器结束残留的 `xray.exe`，再重新启动代理。
5. 可以用系统命令确认占用进程（Windows）：

   ```powershell
   netstat -ano | findstr :10808
   ```

   记下最后一列的 PID，在任务管理器中结束对应进程。
6. 修改端口后如果仍失败，查看日志页的具体错误并重启 FastV。

### Q12. 运行日志在哪里，如何查看历史日志

**现象**

- 需要查看运行记录，或反馈问题需要提供日志。

**原因**

- 日志分为界面内实时日志与持久化文件日志，位置不同。

**解决**

1. 界面内日志：打开 **日志** 页，可查看 Xray 实时输出，支持搜索、等级筛选、暂停、复制与导出为 `.log` 文件；内存中最多保留 1500 条。
2. 持久化日志：`<数据目录>/logs/fastv.log`，Windows 默认 `%APPDATA%\FastV\logs\fastv.log`。
   - 每行格式为 `时间 [级别] [来源] 消息`；
   - 单文件最大 5 MB，轮转为 `fastv.log`、`fastv.1.log`、`fastv.2.log`，最多保留 3 个文件；
   - 启动、退出、崩溃（含堆栈）、内核与代理日志都会写入，适合排查退出后或崩溃现场的问题。
3. 数据目录可在 **设置 → 应用信息 → 数据目录** 查看。
4. 日志中可能包含节点地址与订阅信息，分享前请先移除敏感内容；更推荐使用脱敏的诊断报告（见 [Q13](#q13-遇到问题该如何反馈)）。

### Q13. 遇到问题该如何反馈

**现象**

- 无法自行定位问题，需要在 GitHub 提交 issue 或向维护者反馈。

**原因**

- 仅凭文字描述难以确认运行环境、配置与失败检查项。

**解决**

1. 先按本文对应条目排查，并尝试 **网络诊断 → 一键自检** 与 **网络诊断 → 网络救援**。
2. 打开 **网络诊断**，点击「导出诊断报告」，FastV 会在数据目录生成 `diagnostics-report-*.zip` 并显示路径。
3. 该报告已脱敏，不会包含订阅 URL、密码与节点凭据，包含：
   - `summary.json`：版本、平台、脱敏设置摘要、配置计数、代理状态与自检摘要；
   - `logs.txt`：最近 200 条脱敏代理日志；
   - `selfcheck.json`：完整自检结果（可用时生成）。
4. 到 GitHub Issues 提交问题，附上：FastV 版本、操作系统版本、复现步骤、期望与实际结果、诊断报告 ZIP。日志与截图中如包含订阅地址、节点 UUID、密码或私钥，请先删除。
5. 涉及安全与隐私的内容不要发到公开 issue，请先移除敏感信息。

### Q14. macOS 提示无法打开应用（未签名）

**现象**

- 双击 `FastV.app` 提示「无法验证开发者」「无法打开」，或提示应用已损坏。
- 首次启动被 Gatekeeper 阻止。

**原因**

- 当前 macOS 构建未签名、未公证，系统默认阻止运行。

**解决**

1. 在「应用程序」中**右键点击 `FastV.app` → 打开**，在系统弹窗中再次确认打开；之后可正常双击启动。
2. 若已双击被拦截，可打开「系统设置 → 隐私与安全性」，在安全提示下点击「仍要打开」。
3. 确认下载来源为官方 Releases 页面，并用同页的 `SHA256SUMS.txt` 校验文件完整性；不要运行来源不明的安装包。
4. 若提示「已损坏」且重新下载后仍然出现，请检查下载是否完整（校验 SHA256），或换用其他解压工具重新解压。
5. macOS 专属限制（系统代理/TUN、应用内更新、全局快捷键等暂不提供）见 [用户手册 1.3 节](../USER_GUIDE.md#13-macos)。

### Q15. Linux 启动失败或提示缺少 GTK 与 WebKitGTK

**现象**

- 双击或命令行启动无反应，终端报 GTK3 / WebKitGTK 相关错误。
- 便携包中的 `FastV` 提示没有执行权限。

**原因**

- 系统缺少 GTK3 或 WebKitGTK 4.1 运行库。
- 便携包解压后文件没有执行权限。
- 桌面环境或显示服务（Wayland/X11）导致窗口问题。

**解决**

1. 安装运行库（Debian / Ubuntu）：

   ```bash
   sudo apt install libgtk-3-0 libwebkit2gtk-4.1-0
   ```

   其他发行版请安装对应的 GTK3 与 WebKitGTK 4.1 包。
2. 优先使用 `.deb` 安装包，包内已声明依赖，`sudo apt install ./FastV-<version>-linux-amd64.deb` 会自动补齐依赖。
3. 便携包解压后赋予执行权限再运行：

   ```bash
   chmod +x FastV
   ./FastV
   ```

4. 在终端中启动以查看具体错误信息；必要时尝试在 X11 会话下运行。
5. 仍无法启动时，记录发行版与桌面环境信息后反馈；诊断报告包含平台信息，但需要应用能启动并导出。

### Q16. 配置文件在哪里，换电脑如何迁移

**现象**

- 想备份或迁移订阅、节点、设置；或需要确认数据保存位置。

**原因**

- FastV 把配置保存在用户数据目录中的 `data.json`，不同平台路径不同。

**解决**

1. 在 **设置 → 应用信息 → 数据目录** 查看当前实际路径；默认位置：

   | 平台 | 默认数据目录 |
   |---|---|
   | Windows | `%APPDATA%\FastV` |
   | macOS | `~/Library/Application Support/FastV` |
   | Linux | `~/.config/FastV` |

2. 迁移方式一：退出 FastV 后复制整个数据目录到新机器的相同位置。订阅、节点、设置与快照都会一起带走。
3. 迁移方式二：使用 **设置 → 备份与恢复** 的「导出备份」，在新机器上「导入备份」；或先上传到 WebDAV 再在新机器恢复。
4. 注意：Windows DPAPI 加密的 WebDAV 密码与入站密码无法跨机器/跨 Windows 用户解密，迁移后会被清空，需要重新填写；其他配置不受影响。
5. 也可以通过环境变量 `FASTV_DATA_DIR` 指定自定义数据目录（高级用法），迁移场景更推荐直接复制默认目录。

### Q17. 备份和配置快照有什么区别

**现象**

- 两个功能都在「备份与恢复」中，不确定该用哪个。

**原因**

- 两者用途不同：备份用于跨设备/云端保存，快照用于本机快速回滚。

**解决**

| 对比项 | 备份（本地 / WebDAV） | 配置快照 |
|---|---|---|
| 保存位置 | 本地文件或 WebDAV 云端 | 本机 `<数据目录>/snapshots/` |
| 主要用途 | 换设备、重装、云端容灾 | 改动配置前留还原点、快速回滚 |
| 数量限制 | 无固定上限（受云端空间限制） | 最多 20 个，超出自动删除最旧 |
| 恢复影响 | 覆盖当前全部配置，导入后需重启代理 | 覆盖当前全部配置，回滚前自动创建安全快照 |
| 可否导出 | 本身就是文件 | 可导出为 JSON（与备份格式兼容），也可从备份导入为新快照 |

建议：日常调整设置或规则前创建快照；换设备或长期保存时导出备份，并视需要上传 WebDAV。

### Q18. 密码等敏感数据是如何保存的

**现象**

- 想确认 WebDAV 密码、入站认证密码等敏感信息在本地如何保存，是否安全。

**原因**

- 不同平台使用不同的保护机制。

**解决**

1. 数据目录权限为仅当前用户可访问（目录 `0700`，`data.json` 为 `0600`）。
2. **Windows**：WebDAV 密码与入站认证密码使用 Windows DPAPI 加密后写入 `data.json`（密文以 `enc:v1:` 前缀标识），并绑定当前 Windows 用户与机器。其他用户、其他机器或复制出去的 `data.json` 无法解密；无法解密时该字段会被清空，而不是把密文当作密码使用。
3. **macOS / Linux**：当前没有 DPAPI 等价后端，这两个字段以明文保存在仅当前用户可读的 `data.json` 中，请确保系统账户与磁盘加密安全。
4. 旧版本写入的明文密码仍可正常读取，并在下一次保存时自动转为加密存储。
5. 本地备份、WebDAV 备份、导出的快照 JSON 使用明文配置，**包含**节点凭据与密码，请按敏感文件保管，不要上传到公开位置。
6. 导出的诊断报告默认脱敏，不含订阅 URL、密码与节点凭据；分享前仍建议检查内容。

### Q19. 全局快捷键无效或与其他程序冲突

**现象**

- 按下 `Ctrl+Shift+F` 等快捷键没有反应。
- 修改快捷键后不生效，或提示快捷键无效/重复。

**原因**

- 全局快捷键目前仅在 Windows 上提供。
- 快捷键被其他程序占用，注册失败。
- 组合键不满足规则（缺少 Ctrl/Alt/Shift/Win 修饰键，或主键不在支持范围）。
- 修改后没有保存设置；或启动时快捷键处于关闭状态。

**解决**

1. 确认当前是 Windows，并在 **设置 → 系统集成 → 全局快捷键** 中确认「启用全局快捷键」已开启。
2. 点击「录制」重新设置组合键：必须包含 `Ctrl`、`Alt`、`Shift`、`Win` 中至少一个修饰键，主键仅支持 A–Z、0–9 与 F1–F24，且不能与其他动作重复。
3. 修改后点击「保存设置」才会生效。
4. 如果快捷键被其他程序占用，注册会失败：打开 **日志** 页查看失败原因，换一个组合键即可。
5. 如果启动 FastV 时快捷键开关是关闭状态，重新开启后需要重启 FastV 才会重新注册。
6. 默认快捷键：`Ctrl+Shift+F` 启停代理、`Ctrl+Shift+M` 切换模式、`Ctrl+Shift+N` 下一个启用节点。

### Q20. Windows 启动后白屏，或提示缺少 WebView2

**现象**

- 启动 FastV 后窗口空白、不渲染界面，或提示需要安装 Microsoft Edge WebView2 Runtime。
- 便携版双击后没有界面或立即退出。

**原因**

- Windows 10/11 未安装 WebView2 Runtime，界面无法加载。
- 系统 WebView2 组件损坏或被安全软件拦截。
- 便携版解压不完整或缺少文件。

**解决**

1. 安装 Microsoft Edge WebView2 Runtime（Evergreen Bootstrapper 或离线安装包），安装后重新启动 FastV。
2. 若已安装 WebView2 仍白屏，尝试修复或重新安装 WebView2，并确认安全软件没有拦截 FastV 的 WebView2 进程。
3. 使用便携版时确认压缩包完整解压，且 `Fast-V.exe` 与依赖文件在同一目录。
4. 确认程序没有被移动到一个受限制的目录（如需要管理员权限的系统目录）；必要时放到用户目录下运行。
5. 仍无法启动时，查看 `<数据目录>/logs/fastv.log` 中是否有启动错误记录，并反馈平台版本与安装方式。
